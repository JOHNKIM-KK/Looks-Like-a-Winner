# 2단계 기획서 (SPEC) — Cursor 작업 기준

> **이 문서(`docs/stage2/SPEC.md`)가 2단계의 유일한 기준 문서(single source of truth)다.** 시게루의 07 마스터 스펙 등 다른 문서의 결정은 여기에 반영된 것만 유효하다.
> 이 문서가 2단계의 최우선 기준이다. `docs/stage2/ref/`의 다른 문서와 충돌하면 이 문서를 따른다.
> 정답 이미지: `docs/stage2/storyboard/01~10_*.webp` (명준 승인). 단 마지막 코너 이후~경기 종료 화면은 `docs/stage2/storyboard_finish/`(결승 시안 v2, 2026-11-04 최종 확정)가 대체한다(§3-2).

## 1. 목표
- 기본 말 한 종류 + 기본 기수 한 종류. 레인 색 틴트(안장천·번호판·실크)로 12마리 구분.
- 스킬·돌발 사건 없이 경주 한 판을 처음부터 끝까지(드론 인트로 → 게이트 → 출발 → 주행 → 결승 → 결과).
- 정답 기준은 `docs/stage2/storyboard/`. 장면별 수치는 `STORYBOARD.md`(v2), `STORYBOARD_v1_camera.md`(카메라 거리·렌즈·고도, 말 크기 %), 말 방향은 `HEADING_RULE.md`, 아트 차이는 `ART_DIFF.md`.

## 2. 폐기
- 세로 전용 규격 1080x2340 / 540x1170(GAME_HEIGHT 1170 세로 기준)은 폐기.
- 경주 화면은 모바일·웹 모두 **가로 16:9, 기준 1600x900**.
- 참고: 스토리보드 표의 '엔진 focal(1170h)' 값은 옛 세로 기준 환산값이다. 900h 기준 focal 값을 쓰거나 새 해상도로 다시 환산한다.

## 3. 작업 순서
각 작업 = PR 하나. `feature/renewal`에서 브랜치를 따고 `feature/renewal`로 PR. 순서를 지킨다.

1. **가로 16:9 고정 (1순위)** — 화면 틀·해상도·리사이즈를 1600x900 기준으로. 16:9가 아닌 화면은 레터박스 없이 배경을 늘려 채우고, 세로로 든 폰은 회전 안내(기본안; 다르게 하려면 PR에 적기). HUD·오버레이는 safe-area 안쪽.
2. **드론 인트로 (장면 01~03)** — 경기장 전경(01) → 하강하며 게이트로 초점 이동(02) → 게이트 앞(03). 약 4~5초, 탭하면 건너뛰기. **카메라 각도 1개 유지(2026-11-03 명준 피드백):** 드론 이동은 `start/` 에셋 렌더 카메라에서 끝나고 그 자리에 멈춘다. `drone/` → `start/` 게이트 교체는 이동 마지막 0.4초 크로스페이드.
3. **12칸 게이트 (장면 01~04)** — 게이트는 코드로 그리지 않고 `public/gate/` 에셋을 쓴다(§3-1). 문 닫힘, 말은 칸 안(back과 doors 사이)에 선다. 칸 간격 1.2m(전체 14.4m), 홈 직선 끝 슈트에 위치. PR #19의 코드로 그린(procedural) 게이트는 이 에셋으로 대체하고 쓰지 않는다.
4. **게이트 출발 (장면 04~05)** — 장면 03과 같은 `start/` 카메라에서 카운트다운 노란 숫자(3·2·1, #FFD000 계열, 카운트다운 중 순위·자막 숨김) → 벨 → `openAll`로 문 12개를 4프레임으로 동시 개방 → 12마리가 `exitDir` 방향으로 튀어나감(§3-1). **카메라 각도 1개 유지(2026-11-03 명준 피드백):** 드론 끝부터 출발 뒤까지 컷 없음, 게이트는 `start/` 세트만. 말이 약 1초 달린 뒤 1초 동안 추적 카메라로 보간. `top/` 카운트다운 컷은 `game/gateStart.ts`의 `TOP_COUNTDOWN_CUT` 플래그로 꺼 둔다.
5. **직선·코너 주행 모션** — `HEADING_RULE.md` 그대로. 새 wide 시트 7종(-90/-75/-60/-45/+45/+60/+75, `public/horses/wide/`, `public/jockey/wide/`) 추가, 버킷 히스테리시스(yaw ±10.5°, 세트 15°/18°, 정면·정후면 flip 유지), 각도가 바뀔 때 0.1~0.15초 크로스페이드. 검수는 §3-3 코너 모션 체크리스트로. HEADING_RULE의 `storyboard_v2/sheets/...` 경로는 `public/horses/wide/`, `public/jockey/wide/`로 읽는다. §7 테스트 케이스를 단위 테스트로 넣는다.
6. **스킬·말 개별 능력 비활성화** — 12마리 모두 같은 기본 능력치, 스킬·돌발 사건 off, 스킬 배너 숨김. 능력치·스킬 수치 자체는 지우지 말고 플래그로 끄기만 한다.
7. **카메라 장면별 값** — `STORYBOARD_v1_camera.md` 표의 거리·렌즈·고도대로. 달리는 장면(06)은 거리 16~17m, focal(900h) 약 1275(옛 1170h 환산 1658), 말 길이 화면 폭 20~26%. 코너·백 스트레치(07·08)는 말 12~14%로 무리 전체. 출발(04·05)은 위에서 내려다보며 12칸 전체. 마지막 코너 이후(옛 장면 09·10)는 이 작업에서 하지 않는다 — 결승 카메라는 §3-2(`storyboard_finish/`)대로 9-B에서 한다. 그때까지 결승 직선은 06과 같은 추적 카메라로 둔다.
8. **경기장 주변·톤** — 메인 관중석, 작은 관중석·지붕 건물, 황금빛 들판, 노을 하늘(장면 01 기준). 지금의 녹색 띠는 제거.
9. **순위판·결승·결과 연출 — 두 PR로 나눈다.**
   - **9-A 화면 정보 배치 (작업 1 바로 다음에 한다, 완료)** — 위쪽 순위판(1~3위 큰 카드, 4~12위 작은 칩, 테두리 #5CE1FF, 1위 #FFE14A), 아래 실황 중계 자막과 진행 바, 결과 순위표(1~12위 레인색·이름·1위와 차이, 1위 행 강조)의 배치를 장면 09·10과 똑같이. 이 배치는 결승 시안 v2의 f01~f05와도 같다(변경 없음). 연출은 하지 않는다.
   - **9-B 결승 연출 (맨 마지막)** — §3-2 전체: f01 고정 카메라 → 컷 1번 → 바깥 난간 추적(1.35m·45mm, 슬로우) → 결승선에서 정지, 사진 판정 프레임 약 1초 → 컷 없이 1위 뒤로 올라가며 돌기(45→36mm) → f05 결과 화면(순위표 오른쪽 1/3). 말 머리 위 순위 숫자는 쓰지 않는다(제외). 9-A의 배치는 건드리지 않는다.
   - 실제 순서: 1 → 9-A → 2 → 3+4 → 5 → 6 → 7 → 8 → 9-B.

규칙:
- 모든 PNG는 같은 1600x900 화면에서 잘라낸 것. 각 레이어·문을 `stalls.json`의 x,y(왼쪽 위 기준)에 그대로 놓는다. 크기를 바꿀 땐 레이어 전체를 같은 배율로.

- `start/`에서는 열린 문이 옆 칸과 겹치므로 문을 12번 칸부터 1번 칸 순서로 그린다.

- 장면 03~05는 `start/` 카메라 하나로 컷 없이 잇는다. 드론 → 03만 이동 끝 크로스페이드로 게이트를 바꾼다.
- 알려진 문제: `drone/`·`front/`·`top/`의 10·12번 번호판 숫자가 흐리다(`start/`는 수정됨). 나중에 리무르가 교체할 예정이니 코드에서 고치지 말 것. `front/`의 완전히 열린 문은 칸 끝에서 몇 px 잘린다.

## 8. 코스·주행 규칙 (2026-11-04)
11/3에 나온 '경기장 2배 + 속도 상향' 안은 이 절로 대체한다. 치수 변경은 이 절 내용만 승인됨.

### 8-1. 코스
- 1200m는 화면에 보여 주는 가상 거리일 뿐이다. 게임 트랙은 현재 222m 기준에서 오벌 직선(홈·백)만 2배, 코너 반경 14m·코너 길이는 그대로. 출발 슈트는 11/4 명준 님 확정으로 27m → **55m**(게이트는 `GATE_X`로 슈트 시작점을 자동으로 따라감).
- 현재(코드 `game/track.ts`): 직선 S0 = 40.14m, 코너 1개 = π×14 = 43.98m, L0 = 27 + S0 + C + S0 + C + ⅔S0 = 222.0m.
- 새 값: 직선 S = 80.28m, 출발 슈트 55m, 새 총거리 **L = 55 + 80.3 + 44.0 + 80.3 + 44.0 + 53.5 = 357.0m** (슈트만 +28m, 직선·코너·결승 직선 길이는 그대로).
- 코드: `STRAIGHT_M`은 더 이상 `RACE_METERS`에서 계산하지 않고 **상수 80.3m**로 둔다(`CHUTE_M = 55`, `RACE_METERS = 357`).

| 구간 | 시작~끝 (m) | 길이 (m) |
|---|---|---|
| 출발 슈트 | 0 ~ 55.0 | 55.0 |
| 첫 직선 | 55.0 ~ 135.3 | 80.3 |
| 1·2코너 | 135.3 ~ 179.3 | 44.0 |
| 백스트레치 | 179.3 ~ 259.5 | 80.3 |
| 3·4코너 | 259.5 ~ 303.5 | 44.0 |
| 결승 직선(결승선까지, 홈 직선 ⅔) | 303.5 ~ 357.0 | 53.5 |
| 인코스 진입 구간 (= 출발 슈트) | 0 ~ 55.0 | 55.0 |
| 스퍼트 (+12%, 결승 직선 시작부터) | 303.5 ~ 357.0 | 53.5 |

- 트랙 배치 확정(시게루 결정, 명준 승인 11/4): L = 357.0m(11/4 슈트 55m 확정으로 329.0m에서 변경), 결승선 홈 직선 ⅔ 지점, 출발 슈트 55m, 코너 반경 14m 유지.
- 직선 : 코너 = 실측 75.4%(269.1m, 슈트 포함) : 24.6%(88.0m) ≈ 75:25로 기록(60:40 목표는 폐기).
- 결승 직선 **53.5m(L의 15.0%, 약 9초) 확정**.
- 스퍼트: 마지막 코너를 빠져나오는 303.5m(결승 직선 시작)부터, 속도 **+12%**.
- 인코스 진입 0 ~ 55m(출발 슈트 전체).
- 경주 시간 약 60초. 진행 속도 배율은 **1.99 그대로**: 329m/55초 = 5.98m/s, 357m/60초 = 5.95m/s로 사실상 같음(1.85 × 357/222 ÷ 60/40 ≈ 1.98, 1.99로 357m를 달리면 약 59.7초). 코드 `BASE_SPEED` 1/40.2 → 약 **1/60.0** (= 1/55.3 × 357/329).
- 슈트 55m 영향: 게이트는 `GATE_X = −STRAIGHT/2 − CHUTE`로 자동 이동, 게이트 에셋은 그대로 맞음. 드론 샷 01 목표(`gateViews.ts` targetX) 조정 필요. 메인 관중석 띠는 12m 타일 1장 정도 추가될 수 있음. 테스트 약 5개 값 갱신(`trackLayout`·`standPlacement`·`overlayLayout`·`safety-net`). 결과 순위표 제목 거리도 새 값으로.
- 카메라 줌 그대로, 말 크기 화면 폭 12~26% 유지. 리무르 QA에서 무리면 그때 조정.

### 8-2. 구간별 레인 규칙
- 출발 ~ 55m(슈트 끝): 안쪽으로 강하게 파고든다. 최대 0.6레인/초, 레일 쪽 2~3줄로 뭉침. 말 사이 옆 간격 최소 0.8레인.
- 코너: 안쪽 유지가 기본, 레일 쪽 빈자리가 생기면 진입. 바깥 이동은 0.3레인/초로 제한.
- 백스트레치: 안쪽 당김 절반. 비어 있으면 바깥으로 빠져 추월 가능.
- 결승 직선(마지막 코너 끝부터): 안쪽 당김 0. 앞이 막히면 바깥으로 최대 0.6레인/초, 비어 있으면 그대로. 결승선 쪽으로 갈수록 넓게 퍼지는 그림.
- 막힘 규칙(모든 구간): 이동 방향 쪽 앞 1.5마신 이내나 바로 옆에 말이 겹치면 레인 변경 불가, 속도를 맞춰 따라붙음.
- 접촉·충돌 연출 없음.

### 8-3. 추월
- 시뮬레이션 기준 직선 추월 : 코너 추월 ≈ 3:1 목표.
- 스퍼트 속도 +12%, 303.5m부터 (구간은 8-1 표).
- 시뮬레이션에서 결승 직선 추월이 거의 안 나오면, 홈 직선만 늘리는 안(나)을 시게루와 재검토한다.

### 8-4. 칸 번호 공정성
- 바깥 칸은 초반 구간 기본 속도를 칸별로 소폭 올려 보정. 출발 시차 없음(게이트 에셋 유지).
- 합격: 1만 판 시뮬레이션 칸별 1착률 8.3%±2%p, 결과 표 PR 첨부. 크게 벗어나면 수치 바꾸기 전에 시게루에게 알림.
