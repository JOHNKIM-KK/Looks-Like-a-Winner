# 2단계 기획서 (SPEC) — Cursor 작업 기준

> **이 문서(`docs/stage2/SPEC.md`)가 2단계의 유일한 기준 문서(single source of truth)다.** 시게루의 07 마스터 스펙 등 다른 문서의 결정은 여기에 반영된 것만 유효하다.
> 이 문서가 2단계의 최우선 기준이다. `docs/stage2/ref/`의 다른 문서와 충돌하면 이 문서를 따른다.
> 정답 이미지: `docs/stage2/storyboard/01~10_*.webp` (명준 승인). 화면은 이 10장면과 똑같이 만든다.

## 1. 목표
- 기본 말 한 종류 + 기본 기수 한 종류. 레인 색 틴트(안장천·번호판·실크)로 12마리 구분.
- 스킬·돌발 사건 없이 경주 한 판을 처음부터 끝까지(드론 인트로 → 게이트 → 출발 → 주행 → 결승 → 결과).
- 정답 기준은 `docs/stage2/storyboard/`. 장면별 수치는 `STORYBOARD.md`(v2), `STORYBOARD_v1_camera.md`(카메라 거리·렌즈·고도, 말 크기 %), 말 방향은 `HEADING_RULE.md`, 아트 차이는 `ART_DIFF.md`.

## 2. 폐기
- 세로 전용 규격 1080x2340 / 540x1170(GAME_HEIGHT 1170 세로 기준)은 폐기.
- 경주 화면은 모바일·웹 모두 **가로 16:9, 기준 1600x900**.
- 참고: 스토리보드 표의 '엔진 focal(1170h)' 값은 옛 세로 기준 환산값이다. 900h 기준 focal 값을 쓰거나 새 해상도로 다시 환산한다.

## 3. 작업 순서
각 작업 = PR 하나. `feature/renewal`에서 브랜치를 따고 `feature/renewal`로 PR. 순서를 지킨다.

1. **가로 16:9 고정 (1순위)** — 화면 틀·해상도·리사이즈를 1600x900 기준으로. 16:9가 아닌 화면은 레터박스 없이 배경을 늘려 채우고, 세로로 든 폰은 회전 안내(기본안; 다르게 하려면 PR에 적기). HUD·오버레이는 safe-area 안쪽.
2. **드론 인트로 (장면 01~03)** — 경기장 전경(01) → 하강하며 게이트로 초점 이동(02) → 게이트 정면(03). 약 4~5초, 탭하면 건너뛰기.
3. **12칸 게이트 (장면 01~04)** — 게이트는 코드로 그리지 않고 `public/gate/` 에셋을 쓴다(§3-1). 문 닫힘, 말은 칸 안(back과 doors 사이)에 선다. 칸 간격 1.2m(전체 14.4m), 홈 직선 끝 슈트에 위치. PR #19의 코드로 그린(procedural) 게이트는 이 에셋으로 대체하고 쓰지 않는다.
4. **게이트 출발 (장면 04~05)** — `top/`에서 카운트다운 노란 숫자(3·2·1, #FFD000 계열, 카운트다운 중 순위·자막 숨김) → `start/`로 전환 → 벨 → `openAll`로 문 12개를 4프레임으로 동시 개방 → 12마리가 `exitDir` 방향으로 튀어나감(§3-1).
5. **직선·코너 주행 모션** — `HEADING_RULE.md` 그대로. 새 wide 시트 7종(-90/-75/-60/-45/+45/+60/+75, `public/horses/wide/`, `public/jockey/wide/`) 추가, 버킷 히스테리시스(yaw ±10.5°, 세트 15°/18°, 정면·정후면 flip 유지), 각도가 바뀔 때 0.1~0.15초 크로스페이드. 검수는 §3-3 코너 모션 체크리스트로. HEADING_RULE의 `storyboard_v2/sheets/...` 경로는 `public/horses/wide/`, `public/jockey/wide/`로 읽는다. §7 테스트 케이스를 단위 테스트로 넣는다.
6. **스킬·말 개별 능력 비활성화** — 12마리 모두 같은 기본 능력치, 스킬·돌발 사건 off, 스킬 배너 숨김. 능력치·스킬 수치 자체는 지우지 말고 플래그로 끄기만 한다.
7. **카메라 장면별 값** — `STORYBOARD_v1_camera.md` 표의 거리·렌즈·고도대로. 달리는 장면(06·09·10)은 거리 16~17m, focal(900h) 약 1275~1575(옛 1170h 환산 1650~2050), 말 길이 화면 폭 20~26%. 코너·백 스트레치(07·08)는 말 12~14%로 무리 전체. 출발(04·05)은 위에서 내려다보며 12칸 전체.
8. **경기장 주변·톤** — 메인 관중석, 작은 관중석·지붕 건물, 황금빛 들판, 노을 하늘(장면 01 기준). 지금의 녹색 띠는 제거.
9. **순위판·결승·결과 연출 — 두 PR로 나눈다.**
   - **9-A 화면 정보 배치 (작업 1 바로 다음에 한다)** — 위쪽 순위판(1~3위 큰 카드, 4~12위 작은 칩, 테두리 #5CE1FF, 1위 #FFE14A), 아래 실황 중계 자막과 진행 바, 결과 순위표(1~12위 레인색·이름·1위와 차이, 1위 행 강조)의 배치를 장면 09·10과 똑같이. 연출(슬로모션·배너·머리 위 숫자·등장 타이밍)은 하지 않는다.
   - **9-B 결승 연출 (맨 마지막)** — 아래 9번 세부와 §3-2(§10-A)의 나머지: 측면 고정, 0.5배 슬로모션, 1착 플래시·배너, 머리 위 순위 숫자, 감속·카메라 푸시, 순위표 슬라이드 인, 버튼 등장. 9-A의 배치는 건드리지 않는다.
   - 실제 순서: 1 → 9-A → 2 → 3+4 → 5 → 6 → 7 → 8 → 9-B.

### 9번 세부 (명준 확정)
- 결승 30m 전: 카메라가 결승선 옆에 자리를 잡고, 선두권이 화면 안으로 들어온다.
- 선두가 결승 5m 전: 1초쯤 0.5배 느린 화면으로 긴장감을 준다.
- 1위 통과 순간: 결승 기둥이 번쩍이고 위쪽에 '1착' 배너가 뜬다. 1위 말 머리 위에는 그 말의 레인 색으로 '1'이 붙는다.
- 나머지 말: 결승선을 지나는 순서대로 머리 위에 순위 숫자가 뜨고, 위쪽 순위판도 바로 확정된다.
- 통과 후: 말들이 3초쯤 걸려 천천히 속도를 줄이고, 카메라는 말들을 따라가다가 1위 말 쪽으로 살짝 다가간다.
- 마지막 말 통과 1초 뒤: 장면 10처럼 오른쪽에서 순위표가 밀려 들어온다. 1~12위의 레인 색, 이름, 1위와의 차이가 나오고, 뒤로는 말들이 계속 보인다.
- 순위표가 뜨고 2초 뒤: '다시 하기'와 '나가기' 버튼이 나온다.
(`ref/07_stage2_master_spec.md`의 "결승 후 감속 제외"는 이 내용으로 대체된다.)


### 3-2. 결승 통과 → 경기장 위 순위 발표 (07 마스터 스펙 §10-A 반영)
- 원칙: 경기 종료 후 다른 페이지로 넘어가지 않는다. 경기장 화면(말이 보이는 상태) 위에서 순위를 발표한다. 기준 이미지: storyboard_v2/10_finish_results.png
1. 결승 약 30m 전: 카메라가 결승선 옆(측면)으로 고정, 선두권이 화면으로 들어온다.
2. 선두가 결승 약 5m 전: 0.5배 슬로모션 약 1초.
3. 1위 통과 순간: 결승 기둥 플래시, 화면 상단 '1착' 배너, 1위 말 머리 위에 레인색 순위 숫자.
4. 이후 말마다 통과 순간 머리 위에 순위 숫자가 뜨고 상단 순위판이 실시간 확정된다(12마리 모두).
5. 통과 후 말은 약 3초에 걸쳐 감속(전용 감속 애니메이션은 6단계, 지금은 속도만 줄이고 달리기 루프 재생 속도를 같이 낮춘다). 카메라는 말들을 따라 천천히 패닝하며 1위 말로 살짝 당긴다.
6. 꼴찌 통과 후 약 1초: 오른쪽에서 순위표 패널이 슬라이드 인(시안 10번 배치). 1~12위, 레인색, 이름, 1위와의 차이. 1위 행 강조. 배경의 말들은 계속 보인다.
7. 패널 등장 2초 후 버튼 노출: 다시 하기 / 나가기.
- 사진 판독은 돌발상황이라 2단계에서 제외.
- 검수: 리무르가 10번 이미지와 대조.
- 위 1~7과 9번 세부는 같은 내용이다. 순위표 배치는 9-A, 나머지 연출은 9-B에서 한다.

### 3-3. 코너 모션 검수 (07 마스터 스펙 §8-1 반영, 작업 5 완료 기준에 포함)
- 상태: 역주행 수정은 완료 보고됨(명준·코마). **HEADING_RULE.md의 규칙과 §7 테스트 케이스와 검증 기준(10장면 120마리 시트·flip 120/120 일치)으로 다시 확인**하고, `pose.flipX` 불일치 경고가 0건인지 본다.
- [ ] 몸 방향이 트랙 접선을 끊김 없이 따라간다(보간·스무딩, 툭 꺾이는 스냅 없음).
- [ ] 각도 시트 전환은 HEADING_RULE 히스테리시스(yaw ±3°, 세트 15°/18°, 정면 근처 flip 유지)를 써서 깜빡임이 없다.
- [ ] 코너에서 몸이 안쪽으로 살짝 기운다(기울기 각도 **미정**).
- [ ] 시트가 바뀌어도 질주 루프 프레임(위상)이 이어진다(처음 프레임으로 돌아가지 않음).
- [ ] 레인 간 옆 이동이 부드럽다(순간 이동·떨림 없음).
- [ ] 비교 기준: `storyboard_v2/07_corner.png`, `08_back_final_corner.png`. 리무르가 코너 구간 영상 캡처로 나란히 비교.
- 히스테리시스 수치가 다르면 `HEADING_RULE.md`(작업 5에 적힌 yaw ±10.5°)를 따른다.
- `storyboard_v2/...png` 경로는 `docs/stage2/storyboard/07_*.webp`, `08_*.webp`로 읽는다.

### 3-1. 게이트 에셋 (작업 3·4 공통)
위치: `public/gate/<각도>/` — `back.png`, `front.png`, `sign.png`, `doors/*.png`, `stalls.json`. 설명은 `public/gate/README.md`, 미리보기는 `docs/stage2/gate/preview_*.webp`.

| 각도 | 장면 | 용도 |
|---|---|---|
| `drone/` | 01~03 | 장면 03 카메라(32mm, 고도 5.3°) 그대로 렌더. 03 게이트 정면은 그대로, 01~02 드론 원경에서는 축소해 트랙 위에 놓는다. 문은 칸별 48장 |
| `top/` | 04 | 위에서 약 40° 내려다본 12칸 전체. 카운트다운 화면. 문은 칸별 48장 |
| `front/` | (예비) | 직교 정면도. 문 1세트(`door_*.png`)를 모든 칸에 재사용. 03/04 구도가 맞지 않을 때만 쓴다 |
| `start/` | 05 | 문 열림과 말 출발. 1번 칸이 오른쪽 앞, 12번이 왼쪽 안쪽. 문은 칸별 48장 |

규칙:
- 모든 PNG는 같은 1600x900 화면에서 잘라낸 것. 각 레이어·문을 `stalls.json`의 x,y(왼쪽 위 기준)에 그대로 놓는다. 크기를 바꿀 땐 레이어 전체를 같은 배율로.
- 그리는 순서: back → 말 → doors → front → sign.
- `start/`에서는 열린 문이 옆 칸과 겹치므로 문을 12번 칸부터 1번 칸 순서로 그린다.
- 말 발 위치는 `stalls[i].horseFoot`. 출발 방향은 `stalls[i].exitDir`(화면 단위벡터), 이동 거리 환산은 `exitPxPerM`(미터당 픽셀).
- 문 프레임: closed → opening1 → opening2 → open, 프레임당 약 60ms. 벨이 울리면 12칸이 동시에 연다.
- 말이 칸을 빠져나오면 front·sign 레이어보다 앞에 그린다.
- 장면 전환(드론 → 03 → 04 → 05)은 짧은 크로스페이드나 카메라 줌으로 잇는다.
- 알려진 문제: `drone/`·`front/`·`top/`의 10·12번 번호판 숫자가 흐리다(`start/`는 수정됨). 나중에 리무르가 교체할 예정이니 코드에서 고치지 말 것. `front/`의 완전히 열린 문은 칸 끝에서 몇 px 잘린다.

## 5. 작업 규칙
- 토큰 절약: 필요한 파일만 읽는다. grep은 좁게(파일·폴더 지정). 큰 파일을 반복해서 읽지 않는다. 이미지는 해당 장면만 연다.
- 한 PR에는 그 작업 번호 범위만. 다음 작업을 미리 하지 않는다.
- PR 완료 기준: `npm test` 통과 + 1600x900, 디버그 끈 캡처를 해당 storyboard 장면 이미지와 나란히 PR에 첨부.
- 애매한 값은 storyboard 이미지를 따르고, 정한 값은 PR 설명에 적는다.
